# C-OS SMP並列描画・遊休コア活用設計

## 目的

本設計は、GUIの応答性と描画性能を向上するため、BSPだけが画面のフレームを所有・提示し、遊休APには安全に分離できる高負荷作業を動的に割り当てるものである。現行のAPは実CPU上でCカーネル作業を実行できるが、通常スレッド・GUI状態・VRAMへ同時にアクセスしてはならない。したがって、描画APIへの粗粒度ロック追加や、APからの直接的な `vga_*` 呼出しは採用しない。

| 項目 | 現行実装 | 並列実行時の危険 | 採用する境界 |
|---|---|---|---|
| GUIフレーム | `gui_update()` がBSP上で構築し、`gui_draw()` と `vga_flip()` を実行 | 全ウィンドウ状態・入力状態・描画順序がグローバル | BSPだけがフレーム開始、合成、提示を実行 |
| バックバッファ | `vga.c` のグローバル `backbuffer` | 全プリミティブが同一ピクセルへ無保護で書込み可能 | APは本体バックバッファに書込まない |
| クリップ | `gui_clip_x/y/w/h` と `gui_clip_enabled` がグローバル | AP間でクリップが上書きされ、描画先が不定 | APジョブは不変なローカル矩形を引数で受け取る |
| dirty追跡 | `gui_sys.needs_redraw` をBSPが更新・消費 | APが更新してもフレーム境界と競合 | APは結果とdirty矩形を完了レコードに返す。BSPがマージする |
| VRAM提示 | `vga_flip()` / `vga_flip_rect()` | 書込み中のバッファを表示し、部分フレームになる | BSPだけが完了バリア後に一度だけ提示 |
| AP作業キュー | CPUごとの64項目キュー。APは空なら `pause` | 仕事が偏ると遊休コアが活かせない | ジョブ種別・優先度を持つ共有ディスパッチキューと盗取を追加 |

## 監査結果

実際のデスクトップ描画経路は `gui_lifecycle.c:gui_update()` から `gui_render_loop.c:gui_draw()`、`vga.c:vga_flip()` へ至る。`gui_renderer.c` は二重バッファとdirty矩形を持つが、現行の主フレーム経路では利用されていないため、初期の並列化基盤をここへ追加してもデスクトップの性能・安全性を改善しない。

`gui_draw()` は壁紙、アイコン、すべてのウィンドウ、通知、タスクバー、カーソルを固定順序で直接 `vga_*` に描く。描画中はグローバルクリップをウィンドウごとに更新する。VGAバックバッファ、クリップ状態、ウィンドウ配列、`gui_sys.needs_redraw` には描画用ロックもフレーム所有者チェックも存在しない。このためAPから既存の描画関数へ入ることは不正である。

## フレーム・ジョブモデル

> **BSPは表示フレームの唯一の所有者であり、APはそのフレームが明示的に委譲した、相互に重ならないオフスクリーン作業だけを実行する。**

各フレームは単調増加する `frame_id` を持つ。BSPは入力とウィンドウ状態を確定してから、画面をタイルへ分割する。各タイルは不変な `x/y/w/h`、出力サーフェス、`frame_id`、キャンセル世代、完了先を持つ。APはローカルの一時サーフェスへ描画またはデコードし、完了時に結果を公開する。BSPは全ジョブの完了または期限切れを確認してから、世代が一致するタイルだけを最終バックバッファへコピーし、従来の順序でUIオーバーレイとカーソルを合成して一度だけフリップする。

| ジョブ優先度 | APに委譲できる作業 | BSP専属に保つ作業 |
|---|---|---|
| 高 | JPEG/PNG行ブロック変換、画像XBGR→XRGB変換、gzip展開ブロック | 入力処理、ウィンドウ状態遷移、NetSurf/QuickJSのDOM更新 |
| 中 | 独立画像のスケール、サムネイル生成、フォントグリフのラスター化、タイル塗りつぶし | 既存の `vga_*` を使うデスクトップ描画、グローバルクリップ変更 |
| 低 | プリフェッチ、キャッシュ整備、ログ圧縮、非表示ウィンドウの準備 | `vga_flip*()`、表示バッファの交換、dirty矩形の最終決定 |

## 同期仕様

各ジョブは値渡しした不変入力だけを参照する。APは共有GUI構造や生の `backbuffer` を更新しない。完了通知はリリースストア、BSPの回収はアクワイアロードで行う。フレームが新しくなった場合、BSPは古い世代の結果を破棄できる。BSPはAP待ちのために無限待機せず、締切を越えた未完了ジョブをキャンセルし、同一作業のBSPフォールバックまたは前フレームの安全な内容を選択する。

共有キューはキュー全体のスピンロックだけでなく、CPUローカルdequeと盗取側のCASを用いる設計へ発展させる。初期段階では既存のCPU別キューの負荷指標を見て、BSPが空いているAPへ再配置する。正しいスケジューラ化後に、AP自身が他CPUの低優先度dequeから安全に盗取できるようにする。

## 実装段階

1. 既存の `smp.c` に、仕事種別・優先度・期限・完了レコードを持つ安全な背景ジョブAPIを追加する。これにより空いているAPへ画像変換や圧縮展開を渡せるようにする。
2. APジョブが使う専用のオフスクリーンサーフェスと、`frame_id`・完了バリアを実装する。まだデスクトップの既存プリミティブは移動しない。
3. NetSurf画像変換および大きな塗りつぶしを、非重複タイルのオフスクリーンジョブとして導入する。BSPは結果の取り込みと一回のBitBltのみを担当する。
4. GUIコマンドリストを導入し、BSPが描画命令を不変バッチへ正規化できる範囲だけをタイル処理へ移す。グローバルクリップは廃止し、コマンドごとのクリップ矩形に置き換える。
5. per-CPU実行キュー、ローカルタイマー、リモート起床、ワークスティーリングを備えるSMPスケジューラ完成後、decode/layout/fetchなどの通常カーネルスレッドを段階的に移す。

この順序により、見かけだけの「APで描画」ではなく、フレーム整合性・入力応答性・ページライフサイクルを保った並列化を実現する。
